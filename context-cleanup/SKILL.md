# 清理與預防流水帳

在目前專案內直接清理、矯正與修改相關文件及交接規則，讓下一位貢獻者能辨識「現在有效什麼、還有哪些工作、被什麼阻礙、去哪裡查原因」。成功的指標是現況可信、資訊有唯一去向、歷史按需取得；檔案變短只是輔助證據。

這個 skill 適用一般專案，不要求特定檔名、JSON、jq、資料庫或流程引擎。清理在專案既有的文件與工具內進行，本身不順手引入新的儲存格式、工具或流程引擎——若某個工具確實能增效，那是一個獨立、由使用者拍板的提案，另案處理，不夾帶在清理裡自行移植。

## 先辨識權威與範圍

1. 讀專案 `AGENTS.md` 與相關交接規則，檢查工作樹，辨識實際會在開工時讀取的文件。先看標題、大小與本輪 diff，再讀涉及的片段，因為整份載入歷程會重現正在解決的問題。
1. 找出各類資訊目前的權威位置，包括是否由工具產生；檔名只供參考，專案既有契約優先。若使用者只要求觀察／審查，回報問題與建議即可；要求清理、矯正或預防時，直接完成範圍內可逆修改，不為普通文件編輯新增確認關卡。
1. 清理涵蓋目前狀態、agent 指令、設計與交接文件，以及造成重複追加的相關模板／流程。原始證據、研究內容、正式稽核、發布紀錄及使用者的其他修改保留原意，因為它們可能有完整性或保存要求。

## 資訊去向

| 內容 | 去向與處理 | 原因 |
| :--- | :--- | :--- |
| 現在階段、阻礙、下一步 | 原有狀態摘要；核實後改寫原條目 | 新 session 會把這裡當作現在的事實 |
| 未完成事項 | 既有待辦清單或任務工具；合併重複項、保留驗收條件 | 同一工作要有唯一狀態，避免多份清單互相矛盾 |
| 有效規則、外部要求、決策 | 專案指定的規則／決策／設計文件；保留理由、適用範圍與例外 | 只留命令而刪掉理由，會讓 agent 過度套用或誤用 |
| 已完成工作、單次測試成績、操作經過 | 核實已有的 commit／CI／測試報告；現況只保留仍影響工作的限制或必要連結 | 過去的成功不等於目前通過，逐輪成績會掩蓋現況 |
| 被取代的決策及重要里程碑 | 已保存的決策修訂、commit 或專案既有歷史位置；只留必要的查詢指引 | 需要保留「為何改變」，但不必每次開工載入 |
| 唯一一份、尚未保存的重要歷史 | 先放入專案既有的適當歷史位置；若沒有，建立最小且不在啟動路徑的封存 | 刪除前要確保仍能取得，未 commit 的中間版本不在 Git 裡 |
| 重複、錯誤、已失效的狀態宣稱 | 核實後刪除或修正；仍有疑義者精簡標為待核實 | 未知不能為了整齊被當成完成，也不能把每次改錯再追加成一段 |

日期、長度或 `[x]` 只是線索，不能單獨判定刪除。日期也可能是期限或必要的量測時點；長段落也可能是仍有效的設計理由。

## 執行整理

1. 用目前程式、設定、測試入口或已存在的證據核實衝突。為每項待移除的重要內容確認「保留在哪裡」；聲稱 Git 已保存時，實際確認對應版本含有它，不能只因資料夾有 `.git` 就假設可復原。
1. 將現況與有效規則原地更新，刪除重複敘述並修正互相矛盾的入口；跨 agent 的實質規則留在專案指定的共同來源，其他入口連回它，因為多份手改副本會再次分岔。
1. 使用專案既有狀態工具處理其管理的資料，先確認指令真的存在；不直接改生成檢視或覆寫不可變的修訂／稽核歷史，因為會繞過版本及狀態驗證。沒有這類工具的專案，直接整理原有文件即可。
1. 只為有後續查詢價值的歷程建立去向，先確認目的內容已成功保存，再移除原位置。不要把整份流水帳複製到另一份啟動文件，因為那只是搬移讀取成本。

## 預防再次堆積

在既有交接／更新規則中修正造成追加的指示，通常只需一小段：

- 狀態更新替換原條目；完成事項移出待辦，有價值的里程碑才記歷史，避免每個操作都再生一條紀錄。
- 決策更新同時保留理由與可查的前版；生成檢視透過工具更新，避免現況與修訂各自漂移。
- 交接前檢查目前 diff 是否新增了完成清單、測試日記、過期數字或重複規則；有現成檢查就執行，因為只在 build 檢查會漏掉沒有 build 的工作。
- 開工讀現況與有效規則；歷史用限量搜尋、索引或單條查詢，避免把「持續保存」誤作「每次全讀」。

只修補這次找到的累積來源，保留專案自己的架構。清理本身的過程不另建永久報告；若使用者要求稽核紀錄，記錄必要的去向與未決事項，並讓它按需讀取。

## 驗證與交付

- 檢查 diff、連結、權威來源與仍未解決的矛盾；未完成工作、外部要求、重要例外與唯一歷史均有去向。
- 有工具管理的檢視，執行其一致性檢查；純文件變更檢查格式與連結即可，不為證明清理而重跑無關的大型測試。
- 用 fresh-context 的標準檢視結果：只靠現況入口，是否知道下一步與阻礙？這是人工檢查；沒有獨立 agent 實測就不能宣稱做過跨 agent 驗證。
- 回覆改了哪些權威文件、重要內容的去向、仍待核實什麼；必要時附前後大小，但不以縮小比例取代正確性驗證。

這個 skill 不額外授權 commit、push、發布或清空 agent 記憶。沿用使用者及專案已有授權；若另有結束 session 與記憶遷移的需求，再依可用的 `flush` skill 處理。
